# FinanceCrew 优化实施清单

> 更新日期：2026-08-11
> 原则：先提升可信度和可验证性，再增加功能；每项独立验证、提交和推送。

## P0：可靠性与可信度

- [x] **P0-1 数据可信层**
  - 行情页展示数据源、数据截止时间、延迟类型、复权方式和 fallback 状态。
  - 周期切换后同步更新元数据，不显示上一周期的来源。
  - 验收：A股、港股、美股的日K/分时/分钟周期均能显示接口返回的真实元数据；frontend build 通过。

- [x] **P0-2 前端回归测试与 CI**
  - 为周期切换、市场时区、移动端导航、移动端聊天和回测入口增加最小 Playwright 回归测试。
  - CI 执行 frontend lint、build 和关键测试。
  - 验收：测试可复现已修复问题，CI 全部通过。

- [x] **P0-3 AI 投研运行追踪**
  - 为每次分析保存 run id、模型、工具调用、耗时、状态和证据来源。
  - 先复用现有数据库和事件流，不引入新的可观测平台。
  - 验收：分析历史可查看完整调用时间线，失败步骤可定位。

- [x] **P0-4 文档与产品能力同步**
  - 修正 README 中图表方案、移动端导航、工具数量和数据源说明。
  - 明确实时/延迟、fallback、复权和回测执行口径。
  - 验收：README 描述与代码、API 和界面一致。

## P1：投研闭环

- [ ] **P1-1 ML Signal Lab 产品化**
  - 为现有 `backend/app/ml_signal` 增加受控 API 和诊断页面。
  - 展示样本外指标、Buy precision、特征重要性、训练/测试区间和过拟合警告。
  - 验收：用户可以完成一次单标的信号诊断，不新增第二套 ML 实现。

- [ ] **P1-2 研究实验记录**
  - 关联 Thesis、数据快照、AI 分析、回测参数、结果和 Reflection。
  - 验收：能从一条 Thesis 追溯到对应分析、回测和后续复盘。

- [ ] **P1-3 报告证据分层**
  - 在报告中区分原始事实、确定性计算和 AI 判断。
  - 保存关键假设、数据时间、来源和报告版本。
  - 验收：关键估值和结论可追溯到输入数据与计算假设。

- [ ] **P1-4 Provider 契约统一**
  - 统一 Quote、Bar、Fundamental、News 的元数据字段和 provider 能力说明。
  - 保留现有数据源，不整体迁移到 OpenBB。
  - 验收：业务页面无需自行判断数据源差异，fallback 原因可查询。

- [ ] **P1-5 多模型对比名实一致**
  - 修正当前顺序调用与“并行调用”描述不一致的问题。
  - 增加耗时、token、成本和证据完整度对比。
  - 验收：多模型调用并发执行，单个模型失败不影响其余结果。

## P2：验证需求后再做

- [ ] 组合风险暴露与风险贡献分析。
- [ ] 可保存的研究工作台布局。
- [ ] Paper Trading 和回测偏差分析。

## 暂不实施

- 实盘券商交易。
- 自训练金融大模型。
- 整体迁移到 Qlib 或 OpenBB。
- 新增更多同质化 Agent、技术指标或传统策略。
- 任意拖拽式低代码工作台。
